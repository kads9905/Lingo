Abstract

Lingo translates English into Hindi and Marathi with two systems side by side: MarianMT, a pretrained encoder–decoder, and a hosted LLM steered by tone prompts. It also captions uploaded images with BLIP, speaks translations with gTTS, generates images with SD-Turbo, and measures gender bias. On 20 reference sentences the LLM reached a corpus BLEU of 59.7 on Hindi and 35.6 on Marathi, against 23.3 and 22.4 for MarianMT, while MarianMT answered three to five times faster. MarianMT showed a 43.3 point gender stereotype gap on Hindi and ignored an explicit “she” in every Hindi test sentence. The LLM also favoured masculine forms, but a gender-fair prompt reduced its gap on Hindi from 26.7 to 10.0 points.

1. Introduction

Machine translation is one of the oldest uses of generative language models, and it now sits at a turning point. Dedicated sequence-to-sequence models are small, fast and free to run, but they do one job in one fixed style. General LLMs can follow instructions about tone and audience, but they depend on a hosted service and cost more per request. Hindi and Marathi make the comparison revealing because both mark grammatical gender on verbs, which forces a translator to make decisions the English source never made.

Objectives

  • Translate typed text and image captions into Hindi and Marathi.
  • Compare an encoder–decoder model with an LLM using BLEU, latency and fairness measures.
  • Control tone and register through prompts.
  • Speak the translation aloud.
  • Measure gender bias in translated professions, and test a prompt-based mitigation.

Scope

No model was trained or fine-tuned. The project compares pretrained models and uses prompt-based learning to adapt the LLM. Inputs are limited to 600 characters of English.

2. Generative AI foundations

Lifecycle

Generative and discriminative framing

Both translators are generative: they model the conditional distribution P(target sentence | source sentence) and sample or search for a likely output. A discriminative model instead learns a boundary or score over given inputs. The MiniLM check used here is discriminative in role. It creates no text and only judges whether two sentences agree in meaning.

Probability view

MarianMT produces a probability distribution over the vocabulary at every step. Beam search keeps the most probable partial sentences rather than greedily taking one word at a time. Table 2 in Section 5 shows the finished beams with their log probabilities, which makes the model's uncertainty visible: small changes in wording and punctuation sit very close together in probability.

3. System design

The first design ran all models on Render. Measurement ruled that out: PyTorch with one MarianMT model used 808 MB of memory and two used 1.1 GB, while Render's free instance is limited to 512 MB. The models therefore run on a separate free worker, as the brief allows for heavy models, and the backend without PyTorch measured 64 MB. If the worker is unavailable, LLM translation continues and the interface says the models are not connected.

4. Prompt engineering (U1)

Every LLM request uses a system prompt with three parts: a translator role, a rule that text inside source tags is data and never instructions, and one of four register instructions. The registers are neutral, formal, casual and for children. Two techniques were compared. Zero-shot gives only the instructions. Few-shot adds two worked examples for the chosen language and register. None of the examples appear in the test set.

5. Encoder–decoder translation (U2)

MarianMT is a transformer with a 6-layer encoder and a 6-layer decoder. The encoder turns the English tokens into context vectors. The decoder then generates one target token at a time, using cross-attention to look back at the English. Long input is split into sentences first, because the models were trained on single sentences.

Model selection

The dedicated English to Marathi model, opus-mt-en-mr, was tested first and rejected. It translated “A dog is playing with a ball on the beach” as “the dog is smart”. The multi-target opus-mt-en-inc model with a language token was used instead, raising Marathi BLEU from 5.66 to 22.41.

6. Multimodal features (U3, U4)

An uploaded image goes to BLIP, which writes a short English caption. That caption then follows the normal translation path through both models, and any result can be spoken with gTTS. Spoken output was tested through the API and returned valid MP3 audio for both Hindi and Marathi. The Imagine page adds image generation with SD-Turbo, which meets the requirement for a generation feature.

7. BLEU evaluation

Method

The test set has 20 English sentences across everyday, news, health, education, technical, idiom and polite text, each with one Hindi and one Marathi reference. Corpus BLEU and chrF were computed with sacreBLEU. The Devanagari full stop was normalised first, because the default tokeniser does not separate it from the preceding word. chrF was added because it works on characters, which suits languages with rich word endings. All latencies are medians over the 20 sentences.

Findings

  • The LLM scored higher than MarianMT on Hindi on 18 of 20 sentences, and on Marathi on 16 of 20.

  • BLEU values are modest in absolute terms because free word order and a single reference penalise valid alternatives. They should be compared within this table only.

9. Gender bias (U5)

Method

Twenty professions were chosen, ten stereotypically male and ten stereotypically female. Each was placed in three English sentences with no stated gender, giving 60 sentences per language and system. Past-tense verbs carry gender in both languages, so a rule-based detector read the verb form as masculine, feminine or neutral. Twenty more sentences stated the gender outright, such as “My sister is an engineer. She went home.”, to test whether explicit information is respected. A gender-fair prompt instruction was then tested as a mitigation.

Interpretation

On Hindi, MarianMT followed the stereotype strongly and turned “She went home” into a masculine verb in every test, even straight after “My sister”. This suggests the masculine form is a learned default that the short sentence context does not override. The Marathi MarianMT gap is small, but that does not show fairness, because many outputs were neutral or fragmentary.

The LLM always respected an explicit “she”, which MarianMT failed to do on Hindi. It was not free of bias: with no stated gender it used masculine forms 100.0% of the time for male-coded jobs on Hindi and 73.3% for female-coded jobs, a gap of 26.7 points. On Marathi the gap was 30.0 points. The gender-fair prompt cut these gaps to 10.0 and -3.3 points, mostly by choosing honorific plural forms that carry no gender, and it did so without breaking explicit “she” handling. This is a clear before and after result for a low-cost mitigation.

The detector covers common verb forms only, and a neutral count can hide a mistranslation, so these figures are indicators rather than exact rates.

Hallucination check

MiniLM, a BERT-family model, scores the similarity between the English and its translation. At a threshold of 0.55, it passed 100.0% of 40 correct pairs and caught 100.0% of 40 shuffled pairs (AUC 1.0). That is an easy test. On MarianMT's 10 lowest-BLEU outputs, it flagged only 1. It stops unrelated text, but it misses translations that are wrong yet on topic, such as a literal idiom, so it must not be treated as an accuracy check.

Other safeguards

  • LLM output that is not mainly Devanagari is withheld.
  • Requests are limited per client, which protects the free API quota.
  • API keys are held in platform secrets, and the model worker requires a shared key.
  • A notice appears when a profession is mentioned with no stated gender.

12. Limitations and future work

  • Twenty sentences with one reference each is a small test, so small differences are not meaningful.
  • The reference translations were drafted with AI assistance and should be reviewed by a fluent speaker. This also risks favouring the LLM, because an LLM wrote the references.
  • The keyword safety filter is simple and is not full content moderation.
  • Free hosts sleep when idle, so the first request after a pause is slow.

Future work could add a larger human-translated test set, several references per sentence, human ratings of tone, fine-tuning MarianMT on idioms, and a seq2seq model built for Indian languages.

13. Conclusion

The LLM clearly produced better translations, handled idioms that MarianMT took literally, and alone could change tone. MarianMT remained faster, cheaper and self-contained, and its attention and beam outputs made its behaviour easy to inspect. The main lesson is that neither fluency nor a single score is proof of quality: gender errors and hallucinations both read naturally, and the meaning check missed most subtle errors. Translation systems for gendered languages need measured bias tests, not only accuracy scores.
